# 日本語の文体：natural-japanese スキルに委ねる

grill 系スキル（`grill-me` / `grill-you` / `grill-product` / `grill-loop`）が散文の成果物を
書き上げるときの共通手順。各スキルの SKILL.md はここを参照する。
**この方針を変えるときはこのファイルだけを直す。**

## なぜ外部スキルに委ねるのか

AI は自分の文体の癖を認識しにくい。「〜することができる」のような冗長な言い回しも、
全節が同じ厚みになる均質さも、書いている側からは見えない。
[natural-japanese](https://github.com/coji/natural-japanese)（MIT, coji 作）は
形態素解析で禁止語・翻訳調・リズムの単調さを機械的に検出し、直すかどうかの判断だけを
AI に残す設計になっている。**このプラグインで同じ検出器を持つ意味はない。**

## 依存させない

natural-japanese は別プラグインで、入っていない利用者がいる。呼ぶ前に Skill ツールの一覧に
`natural-japanese`（プラグイン経由では `natural-japanese:natural-japanese`）があるか確かめ、
**なければ何も言わずに素のまま書く**。このプラグインの動作は natural-japanese の有無に
左右されてはならない。

## いつ呼ぶか

対象は**ユーザーの手元に残る散文の成果物だけ**。設計書・要件定義書・ループ設計書・理解メモを
提示するか保存する直前に、1 回だけ通す。

Q&A の質問ターン、確認の一言、進捗報告には使わない。毎ターン呼ぶと対話のテンポが壊れるうえ、
そもそも表と箇条書きが主体の出力には効かない。同じ理由で、レビュー系
（`pr-review` / `commit-review` / `gui-event-audit` とレビュー系 agent）の出力も対象外とする。

## 手順

1. **クイックモードで呼ぶ。** 引数は `quick`。数十秒で終わり、lint 1 回と通読で収束する。
2. **フルは頼まれたときだけ。** ユーザーが「しっかり」「時間をかけていい」と言った場合、
   または対外・経営向けの文書のときに `full` を渡す。サブエージェント 3 並列で
   5〜20 分かかるため、こちらから勝手に選ばない。
3. **成果物の構造は変えさせない。** 各スキルの `references/*-template.md` の節立てが正であり、
   natural-japanese が直すのは文であって章構成ではない。節が落ちたら戻す。
4. **中間ファイルを残さない。** natural-japanese は判断台帳や lint の JSON を作る。
   完了時に消えていることを確認する（スキル側の後片付け工程が担当する）。

`uv` がない環境では natural-japanese が自前で手動チェックリストに切り替える。こちら側で
分岐を持つ必要はない。
