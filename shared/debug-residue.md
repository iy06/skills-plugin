# デバッグ残骸の既定検出パターン

`commit-review` skill が **rules の有無にかかわらず必ず実施する**組み込みチェックの既定値。

プロジェクト側で例外を許可したい場合は `.claude/rules/shared/debug-residue.md` を作る。
存在すればそちらが優先される。書き方はこのファイルと同じ形式でよい。

## BLOCK と WARN の分け方

パターンごとの判定は暗記ではなく、次の一線で決まる。

- **BLOCK** — そのまま本番に出ると**実行が止まる / テストが黙って無効になる**もの。
  気づかずにマージされると、検知に時間がかかるうえ被害が大きい
- **WARN** — 出力ノイズや消し忘れ。動作は壊れないが、放置すると本番ログを汚し、
  機密情報の漏洩経路にもなりうる

新しい言語やフレームワークのパターンを足すときも、この一線で振り分ける。
重大度の一般的な考え方は [`severity.md`](./severity.md) を参照。

## パターン

diff に **追加** されている場合のみ検出する（既存行は対象外）。

| パターン | ラベル | 言語 | BLOCK の理由 |
|---|---|---|---|
| `debugger;` | BLOCK | JS/TS | ブラウザ / Node が実行時に停止する |
| `.only`, `.skip`（テスト） | BLOCK | JS/TS テスト | 他のテストが黙って実行されなくなる |
| `dump(`, `dd(`, `var_dump(` | BLOCK | PHP/Laravel | `dd()` はレスポンスを打ち切る |
| `binding.pry`, `byebug` | BLOCK | Ruby | 実行が停止して応答が返らなくなる |
| `console.log`, `console.debug` | WARN | JS/TS | — |
| `print(`, `pprint(`（src 配下） | WARN | Python | — |
| `fmt.Println`（main 以外） | WARN | Go | — |
| `TODO`, `FIXME`, `XXX`（新規追加分のみ） | WARN | 全言語 | — |

`TODO` / `FIXME` / `XXX` は厳密にはデバッグ残骸ではないが、「後で消すつもりで残る」
という失敗の仕方が同じなので同じ枠で見る。

## WIP コミットでの扱い

コミットメッセージに `wip` / `WIP` / `tmp` / `temp` を含む場合、`TODO` / `FIXME` の
WARN は出さない。未完成であることを本人が宣言しているものに、未完成だと指摘しても意味がない。

BLOCK のパターンは WIP でも通常どおり検出する。実行を止める種類の残骸は、
完成度とは無関係に事故になるため。
