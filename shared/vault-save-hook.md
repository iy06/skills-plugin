# 成果物の Vault 保存フック：共通方針

grill 系スキル（`grill-me` / `grill-you` / `grill-product`）が成果物を確定させた後、
Obsidian Vault への保存を提案するときの共通の約束。各スキルの SKILL.md はここを 1 行で参照し、
スキル固有の「いつ・何を」だけを自分側に書く。**方針を変えるときはこのファイルだけを直す。**

## 保存は提案であって、自動実行ではない

成果物が確定したら AskUserQuestion で保存の可否を聞く。ユーザーが「保存しない」を選んだら
そこで終わり、チャット内に提示したまま次へ進む。記録が要るかどうかは本人にしか分からないし、
黙って書き出すと、利用者が把握していないファイルが Vault に増えていく。

**提案は一度だけ。** 断られた後に言い方を変えて聞き直さない。

## 保存先は vault-save に委ねる

保存先の Vault もフォルダも `vault-save` スキルが決める。**各スキルが渡すのは成果物の本文と
種別だけ**で、パスの知識は持たない。

理由は移植性。このプラグインは利用者ごとに違う環境に入り、Vault の構成も置き場所も一定では
ない。`01-Projects/` のような具体名を各スキルが持ち始めた時点で、そのスキルは特定の Vault
構成に固定される。

個人 Vault と共有 Vault の使い分けも `vault-save` の責務。**AskUserQuestion の選択肢に Vault 名
を出さない** — 出した時点でその判断が漏れている。聞くのは「保存するか」「何を保存するか」まで。

## vault-save が無ければ、提案そのものをしない

Skill ツールの一覧に `vault-save` が無い環境では、保存の提案を出さずに黙って飛ばす。Vault を
使っていない利用者に、動かない選択肢を見せる意味はない。各スキルには「保存パスを聞いて
Markdown で書き出す」既存の経路が残っているので、機能が失われるわけではない。
