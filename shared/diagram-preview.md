# 図の出し方：HTML ファイルを書き出してブラウザでプレビュー

grill 系スキル（`grill-me` / `grill-you` / `grill-product` / `grill-loop`）が図を見せるときの共通手順と、
図解 HTML のデザインの決まり。各スキルの SKILL.md はここを参照する。

同じ方針を担うファイルが 3 つある。**変えるときは 3 つを揃えて直す。**

| ファイル | 役割 |
|---|---|
| `shared/diagram-preview.md`（このファイル） | 手順と、どの構造にどの部品を使うかの規則 |
| `shared/diagram-style.css` | トークンと部品の CSS。生成する HTML に貼り込む唯一の源 |
| `shared/diagram-kit.html` | 部品の見本と雛形。ブラウザで開けば一覧になり、生成時はここから写す |

## なぜチャットに貼らないのか

ターミナルの Claude Code は応答中の HTML を描画しない。貼るとタグがそのままコードとして表示され、
図として読めない。Mermaid も同じ理由で使わない。

## 手順

1. **自己完結した HTML を組み立てる。** 骨組みは次のとおり。`<style>` には `shared/diagram-style.css` の
   中身を `cat` してそのまま貼る（手で書き直さない、抜粋しない）。外部 CSS / JS / CDN / フォントには
   依存させない（オフラインでも開けるように）。

   ```html
   <!DOCTYPE html>
   <html lang="ja"><head><meta charset="utf-8">
   <title>（主題を短い名詞句で）</title>
   <style>/* shared/diagram-style.css の中身 */</style>
   </head><body><div class="page">
     <p class="eyebrow">（スキル名や文脈）</p><h1>（主題）</h1>
     <p class="meta"><span>対象: …</span><span>日付</span></p>
     …（部品は shared/diagram-kit.html から写す）…
   </div></body></html>
   ```

2. **一時ファイルに書き出す。** 衝突しない名前にする（例 `"${TMPDIR:-/tmp}/grill-<topic>.html"`、
   同一セッションで複数出すなら連番を付ける）。
3. **既定ブラウザで開く。** macOS `open <file>` ／ Linux `xdg-open <file>` ／ Windows `start "" <file>`。
   ブラウザ操作・プレビュー系の MCP ツールが使えるならそれでもよい。
4. **チャットにはパスと図の要点だけを 2〜3 行で添える。** 生の HTML は貼らない。
5. **開けない環境**（ヘッドレス / Web セッション等）では、ファイルパスを伝えてユーザーに開いてもらう。

## デザインの決まり（2026-09-04 確定）

過去の出力は「文字 12〜13px、全部が枠、矢印は文字、配色はファイルごとに別」で読みづらかった。
実物と候補を並べて見比べた結果、次に固定した。CSS のトークンを変える以外の逸脱はしない。

### 文字と幅

- 本文 15px、行間 1.8、幅 880px（`--fs` / `--measure`）。図だけ横に長いときは `.fig` の中で
  横スクロールさせ、本文幅は広げない
- 箇条書きは 1 項目 1 文。補足は「。」で区切って同じ項目に続ける
- **英語の書き分け**: 識別子（パス・ヘッダ名・変数名・コマンド・キー名）は `<code>`、それ以外の
  英単語（製品名・概念名。例: *Redis*, *denylist*, *JWT*）は `<i>`。日本語は素のまま
- 用語は初出で短い言い換えを添える（例: クレーム＝トークンに入っている項目）。図版の見出しに
  専門語だけを置かない
- テーマは OS 追従（ライト / ダーク両方をトークンで持つ）

### 色の意味

色は意味にだけ使う。装飾には使わない。

| トークン | 意味 | 使う場所 |
|---|---|---|
| `--accent` | 今回つくる部分・論点 | `.box.hl` / `.nd.hl` / 番号バッジ |
| `--ok` | ある・済・有効 | 差分マップの左列、進む条件のピル、`.tag.ok` |
| `--ng` | 無い・欠・失敗 | 差分マップの右列、401 などの終端、`.tag.ng` |
| `--warn` | 不整合・要確認・変更 | 差分マップの `!`、`.tag.warn` |
| `--neu` | 対象外・既存 | `.tag.neu`、終端状態の塗り |

### 構造ごとの部品

| 構造 | 既定の部品 | 切り替える条件 |
|---|---|---|
| 処理の流れ | 横並び `.flowgrid`（番号バッジ、「・」注記、進む条件のピル、分岐は下に落として合流） | 6 ステップ以上、または補足が長いなら縦レール `.rail` |
| 経路と差分（層ごとに、あるもの / 無いもの） | 3 列の差分マップ `.diff`（経路 ｜ ＋ある ｜ −無い、不整合は右列に `!`） | 列見出しの語は内容に合わせる: ある/無い、実装済み/未実装、現状/追加、一致/不一致 |
| コンポーネント間の関係 | インライン SVG（矢印ラベルはピル、主経路に番号、別系統は点線＋凡例） | ノード 9 個以上、または層構造そのものが主題ならレーン `.lanes` |
| 状態遷移 | インライン SVG ＋ 遷移表のセット（遷移番号で対応、条件と副作用は表にだけ） | 状態 6 個以上なら図を省いて表だけ |
| データの形 | 例つきの木 `.tree`（1 行目に対象の一言、列は 名前 / 型 / 例 / 説明） | 入れ子が無く説明が長いなら表 `.tbl`（見出しは 項目 / 型 / 例 / 説明） |

### 図の描き方

- **矢印には必ずラベルを付ける。** 「何を送るか・何をするか」が情報。ラベルの無い矢印は描かない
- **1 図 1 主張。** `<figure>` で包み、`<figcaption>` に「この図が示すこと」を 1〜2 文で書く。
  説明の文章は図の中に入れず、caption か本文に置く
- **番号は順序を表すときだけ。** 処理の流れ、要求の主経路、遷移。同じ対象を別の図で描くときは
  番号を揃える（処理の流れの 3 と構成図の 3 は同じ動作）
- **強調は 1 図に 1 種類。** 今回つくる部分を `--accent` で示す。それ以外は状態色だけ
- **横並びの箱の注記は 1 行 9 文字まで、進む条件のピルは 3 文字まで。** 収まらなければ縦レールにする
- 描くかどうかは下の「図を描くかどうかの判断」に従う

### SVG の約束

`shared/diagram-kit.html` の 4 と 5 に見本がある。座標はその見本を基準にずらす。

- `viewBox` で大きさを決め、CSS で `max-width:100%` に縮める。横に流れる図は横長、層は縦長
- ノードは `rect` 130×56（状態は 140×50 の丸端）。名前は `.tt`、補足は `.ts`。隙間は 90 以上
- 矢印は `path` ＋ `marker-end="url(#ah)"`。強調は `.hl` ＋ `url(#ah-acc)`、別系統は `.ds`
  ＋ 図の下端に凡例
- ラベルは `rect.pl`（高さ 18、rx 9）＋ `text.pt` を線の上に中央で。幅 ≈ 日本語 11.5/文字 ＋
  英数 6.5/文字 ＋ 14。長いラベルは 2 行にせず、短い語に言い換えるかピルの下に `.ts` で補足
- 番号は `circle.nc`（r 8）＋ `text.nt` を矢印の根元の斜め上
- 線と文字の色はクラス経由で CSS トークンを使う（`currentColor` / `var(--…)`）。SVG の中に
  `<style>` や `<script>` を書かない
- `role="img"` と `aria-label` に、図が示す主張を 1 文で入れる

## 図を描くかどうかの判断

図は理解の補助であって、描くこと自体は目的ではない。テキストや短いコード例で十分なら描かない。
逆に、次のような構造の理解が要る場面では惜しまない。

- 処理の流れ（時系列・条件分岐）
- コンポーネント間の関係
- データの形
- 状態遷移
- 層ごとに「あるもの・無いもの」を突き合わせる場面（差分マップ）
