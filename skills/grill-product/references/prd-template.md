# 要件定義書テンプレート

`grill-product` の Step 8 で提示する要件定義書の雛形。**Step 1〜7 の合意が取れてから**読む。

該当しないセクションは省略してよい。小さなアプリなら概要・コアバリュー・機能要件だけで
完結することもある。**過剰なボリュームより、コアが決まっていることが大事**。

```markdown
# <アプリ名> 要件定義書

## 1. 概要
- アプリ名 / 一行説明
- 種別（新規 / 既存改修）

## 2. 背景と目的（Why）
- 解決したい課題
- 既存の代替手段との違い

## 3. ターゲットユーザー（Who）
- ペルソナ
- 主要ユースケース

## 4. コアバリュー
- このアプリが提供する 1〜3 個の核となる価値

## 5. 機能要件
### Must（必須）
### Should（重要）
### Could（あれば嬉しい）
### Won't（今回はやらない / スコープ外）

## 6. 非機能要件
- 性能 / 可用性 / セキュリティ / アクセシビリティ / 対応環境 など

## 7. 成功指標
- 定量 / 定性

## 8. 技術スタック（任意）

## 9. 備考
- 未確定事項、今後の検討事項
```

## 埋めるときの注意

- **「5. 機能要件」の Won't は必ず書く。** 「やらないこと」の明示は要件定義の重要な役割で、
  後から「やるはずだった / やらないはずだった」の認識ズレを防ぐ
- **「7. 成功指標」は最低 1 つ決める。** ここが空だと「作ったけど、これで良いのか分からない」
  状態になりやすい。個人開発なら「自分が毎日使えているか」で十分
- **「9. 備考」に未確定事項を正直に残す。** すべての論点を潰そうとすると永久に完成しない
