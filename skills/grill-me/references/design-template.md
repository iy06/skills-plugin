# 設計書テンプレート

`grill-me` の Step 6 で提示する設計書の雛形。**Q&A で論点が出し切れてから**読む。

該当しないセクションは省略してよい。小さな変更なら要件と変更対象だけで完結することもある。
テンプレートに縛られず、タスクに合ったボリュームにする。

```markdown
# <機能名> 設計書

## 要件
### 機能要件
### 非機能要件

## 設計方針

## 変更対象
（ファイル・モジュール一覧、前提条件、スコープ外を含む）

## データモデル / API / 型定義
（該当する場合のみ）

## 処理フロー
（エラーハンドリングを含む）

## テスト方針

## 完了条件
（機械検証できる形で。テストの pass、コマンドの exit 0、ファイルの存在など）

## 備考
（未確定事項、今後の検討事項）
```

## 埋めるときの注意

- **「変更対象」にスコープ外を明記する。** 何を触らないかを書いておくと、実装フェーズでの
  スコープクリープを防げる
- **「備考」に未確定事項を正直に残す。** すべての不確実性を潰そうとすると Q&A が終わらない。
  「実装に入れるだけの解像度」が得られたら、残りはここに書いて実装フェーズで判断する
- **「完了条件」には機械検証できる形だけを書く。** 「いい感じにする」「使いやすくする」は完了条件に
  ならない。テストの pass、コマンドの exit 0、ファイルの存在など、pass / fail が自動で付く形にする。
  このセクションは `grill-loop` が issue 本文の完了条件ブロックにそのまま流用し、`code-review` が
  「設計 → 実装」の照合の物差しに使う
- **「処理フロー」を図で示す場合**は、プラグインルートの `shared/diagram-preview.md` に従う
